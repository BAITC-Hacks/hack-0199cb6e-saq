# SPEC_UI — интерфейс (`web/`, Next.js 16)

Пользователь — менеджер закупа (живёт в Excel) и утверждающий руководитель. Принципы: **таблица прежде всего**, каждое число
объяснимо в 1 клик, ничего не уходит наружу без человека, RU/KZ везде, работает офлайн.

## 1. Дизайн-система

Токены в `web/app/globals.css` (`:root` + `[data-theme="dark"]`), Tailwind v4 `@theme`. Стиль — по мотивам ekt.kz, **без логотипа EKT**
(нужно разрешение); название продукта в шапке: «ЕКТ · Закуп» + бейдж «Прототип».

| Токен | Светлая | Тёмная | Назначение |
|---|---|---|---|

- Шрифты: **PT Sans** (текст) и **PT Mono** (коды, артикулы) через `next/font/google` — файлы встраиваются при сборке (офлайн, без
  запросов к Google в рантайме). Числа — `font-variant-numeric: tabular-nums`, выравнивание вправо.
- Форматирование — только `web/lib/format.ts`: `Intl.NumberFormat('ru-KZ')` (для kk — тоже `ru-KZ` числа, чтобы разделители
  совпадали), `₸` после числа, даты `дд.мм.гггг`, месяцы — локализованные короткие названия.
- Статус всегда = цвет **+ иконка + текст** (lucide: `AlertOctagon` critical, `AlertTriangle` high, `Clock` medium, `CheckCircle2` none).
- Плотность: переключатель «Компактно/Удобно» (в `localStorage`, try/catch).
- Иконки — lucide-react; компоненты — shadcn/ui (Button, Tabs, Sheet, Dialog, Command, Badge, Tooltip, Toast, Slider, Table-примитивы).
- Тёмная тема — поддерживается токенами; по умолчанию светлая.

## 2. Навигация и каркас

Левое меню (сворачиваемое): Главная · Данные · Подсказки ИИ · Расчёт · Заказы · Аналитика · Методология · Аудит.
Шапка: поиск (`Ctrl+K`, семантический), кнопка «ИИ-помощник» (`Ctrl+J`, правая панель), переключатель **RU | ҚАЗ**, пользователь/роль,
индикатор ИИ (зелёный — модель прогрета; серый — ИИ недоступен, ядро работает), бейдж «Офлайн-режим: данные не покидают компьютер».

## 3. Экраны

1. **`/login`** — логин/пароль, переключатель языка. Ошибки без раскрытия, что неверно.
2. **`/` Главная** — карточка **ИИ-брифинга** (стрим, бейдж «Сгенерировано ИИ», ссылки на SKU), KPI последнего расчёта
   (к заказу ₸, позиций, critical/high, избыток ₸, дата данных), CTA «Новый расчёт», список последних прогонов.
3. **`/data` Данные** — зона перетаскивания (до 20 файлов), кнопка «Загрузить демо-данные» (admin, `POST /datasets/local`),
   таблица распознанных файлов (профиль, поставщик, строк, статус; неизвестный → кнопка «Разобрать с ИИ» → экран 4),
   **отчёт качества**: группы по уровню, раскрываемые примеры, график сверки «транзакции vs месячный отчёт» по поставщикам
   (линия отношения, коридор 0.85–1.15), счётчик «Удалено персональных данных: N».
4. **`/data/import` Мастер ИИ-импорта** — предпросмотр первых строк, таблица колонок: заголовок · примеры · предложенное поле
   (select) · уверенность (бар) · пояснение; распознанные колонки поставок (документ/канал/дата/ETA); имя профиля; «Сохранить профиль».
5. **`/data/suggestions` Подсказки ИИ** — карточки по типам: «Замена артикула», «Снят с производства (EOL)», «Под заказ»,
   «Единицы закупки», «Волна ввода», «Возможно выводится (!!!)». В карточке: товар, исходный текст (подсветка фрагмента),
   предложение, уверенность, метод (правило/ИИ), кнопки «Принять»/«Отклонить», массово «Принять все с уверенностью ≥ 0.9».
   Счётчики и фильтры. После принятия — тост «Учтётся в следующем расчёте» + кнопка «Пересчитать».
6. **`/runs/new` Параметры расчёта** — поставщики, категории, дата расчёта, сроки по каналам (предзаполнены, источник: «из данных»/
   «по умолчанию»), период пересмотра, уровни сервиса A/B/C/NEW, максимум покрытия, таблица «План прироста» (область/ключ/%/примечание),
   «Рассчитать» (прогресс + время).
7. **`/runs/[id]` Рекомендации** — полоса KPI; вкладки поставщиков (**Systeme Electric | ИЭК**) → подвкладки каналов;
   фильтры-чипы (срочность, ABC, класс спроса, флаги, «только к заказу»), поиск (семантический).
   Виртуализированная таблица (TanStack): срочность · код (mono) · артикул · наименование (2 строки) · ABC/класс · остаток (+бейдж
   «оценка») · в пути (+ближайшая ETA) · прогноз/мес · покрытие (мес, подсветка <1 и >4) · **рекомендовано** (ед. продажи и закупки,
   например «9 бухт = 2 745 м») · кратность · сумма ₸ · краткое обоснование · иконки флагов.
   Клавиатура: ↑↓ навигация, Enter — карточка, `E` — правка (в заказе). Выбор строк → «Создать заказ поставщику».
   Баннер для ИЭК: «Остаток ИЭК оценён по данным на 01.09 и продажам 1–22.09».
8. **Карточка SKU** (правая панель `Sheet`, ширина 720 px; на мобильных — на весь экран):
   шапка (название, код, артикул, чипы ABC/класс/жизненный цикл/флаги), **график** (ECharts): столбцы факта продаж; линия очищенного;
   пунктир восстановленного; розовая заливка месяцев с доступностью < 0.95 (подсказка «доступность 57%»); ✕ на месяцах с разовыми
   заказами (подсказка со строками); линия прогноза + коридор; вертикальные маркеры прихода поставок (ETA, документ); «сегодня».
   Вкладка «Проекция»: остаток по дням, дата дефицита, приходы.
   **Waterfall** (горизонтальные бары, итог выделен), список причин (текст локали), чипы контрфактов
   («без восстановления stockout: 5 540», «без исключения разовых: 8 120», «по среднему: 1 900»), таблица разовых строк, поставки, аналоги,
   пометки (очищенные), **what-if**: слайдеры «в пути ±», «остаток ±», «срок поставки ±дн», «прирост %», «уровень сервиса» →
   `POST /whatif` (debounce 300 мс) → дельта количества и срочности.
9. **`/orders/[id]` Заказ** — статус-лента (Черновик → На утверждении → Утверждён/Отклонён → Выгружен), строки с правкой количества
   (при |Δ|>20% — обязательное поле причины), итоги, действия по роли, при `four_eyes` подсказка «Утвердить может другой сотрудник».
   Блок **«Сводка для утверждающего (ИИ)»**. Экспорт: «1С (xlsx)», «Таблица менеджера (xlsx)», «CSV».
   Кнопка «Черновик письма поставщику (ИИ)» → модалка с текстом, «Копировать», надпись «Отправка выполняется сотрудником вручную».
10. **`/analytics`** — тренды спроса по линейкам/категориям (шт, 32 мес + прогноз), профиль сезонности поставщика (наш по шт vs файл
    партнёра), избыток ₸ (топ-20), распределение срочности × ABC (тепловая карта), результаты бэктеста (WAPE/bias: наш vs менеджер vs наивный).
11. **`/methodology`** — рендер `docs/METHODOLOGY.md` (ru; kk — резюме), схема конвейера.
12. **`/audit`** — таблица событий, фильтры, кнопка «Проверить целостность» (`/audit/verify`, зелёный/красный результат).
13. **ИИ-помощник** (глобальная правая панель, `Ctrl+J`): история, поле ввода, **кнопка микрофона** (удерживать — запись ≤ 30 с →
    `/ai/voice` → текст в поле, пользователь подтверждает Enter), стрим ответа, ход работы («Ищу товары…», «Считаю what-if…» из событий
    `intent/tool_call`), ссылки `[[sku:…]]` → карточка, бейдж проверки чисел (✓ «Все числа сверены с данными» / ⚠ список несверенных),
    бейдж «Сгенерировано ИИ · локально», быстрые подсказки-вопросы (RU/KZ).
14. **Палитра `Ctrl+K`** — семантический поиск товаров (`/ai/search`) + команды навигации; результат → карточка SKU.

## 4. Состояния
Каждый экран: скелетоны при загрузке, пустые состояния с действием («Загрузите данные»), ошибки с `Problem.title` + «Повторить»,
ИИ недоступен → панели ИИ показывают объяснение, ядро работает. Тосты для действий. Подтверждение деструктивных действий (отклонение).

## 5. Доступность
WCAG 2.2 AA: контраст текста ≥ 4.5:1, элементов графика ≥ 3:1; фокус видим; все кнопки-иконки с `aria-label`; таблица с `role=grid`
и клавиатурой; графики — с текстовой альтернативой (краткая сводка под графиком); `prefers-reduced-motion`.

## 6. i18n (next-intl)
`web/messages/ru.json`, `web/messages/kk.json`, одинаковые ключи (тест `npm run i18n:check`). Локаль — cookie + профиль пользователя.
Тексты от API приходят как `I18nText` — показывать поле текущей локали. Глоссарий (использовать единообразно, вычитка носителем):
заказ — тапсырыс; поставщик — жеткізуші; остаток — қалдық; склад — қойма; дефицит — тапшылық; избыток — артық қор; прогноз — болжам;
сезонность — маусымдылық; спрос — сұраныс; срок поставки — жеткізу мерзімі; товар в пути — жолдағы тауар; страховой запас — сақтандыру қоры;
утвердить — бекіту; отклонить — қабылдамау; срочность — шұғылдық; расчёт — есеп; рекомендация — ұсыныс; поиск — іздеу; данные — деректер.

## 7. Техника
- Данные: server components для списков, client components для таблицы/графиков/панелей. Фетчинг через `web/lib/api.ts`
  (CSRF-заголовок, обработка `Problem`, zod-проверка на границе).
- **Моки**: `NEXT_PUBLIC_MOCK=1` → `web/lib/mock.ts` отдаёт `contracts/examples/*.json` (B работает без бэкенда первые 2 часа).
- Proxy API: `next.config.ts` rewrites `/api/v1/:path*` → `http://127.0.0.1:8000/api/v1/:path*`; SSE — route handler (SPEC_API §3).
- Безопасность: заголовки и CSP — `web/proxy.ts` (в Next 16 бывший middleware) с nonce; `Permissions-Policy: microphone=(self)`.
- Никаких внешних скриптов/шрифтов/картинок в рантайме. `localStorage` — только UI-настройки (плотность, свёрнутое меню), в try/catch.
