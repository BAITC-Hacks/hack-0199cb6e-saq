# SPEC_DATA — форматы данных партнёра и каноническая модель

Описание получено анализом реальных выгрузок (22.09.2026). Codex реальные файлы **не видит** — реализуй по этому описанию и
проверяй на синтетике, которая воспроизводит те же форматы (§8).

## 1. Общие правила парсинга

- Тип файла определяется по **заголовкам** (fingerprint), а не по имени. Имена бывают с двойными пробелами и кириллицей
  (`MOQ  ИЭК.xlsx`).
- Все книги открывать через `ekt_adapters.xlsx_safe.open_workbook(path, need_comments: bool)`:
  `data_only=True`, `keep_links=False`; `read_only=True`, если комментарии не нужны (в read_only комментарии не читаются).
- Коды 1С: `str`, `strip()` пробелов и `\xa0` по краям, больше ничего. Регистр и `_` сохраняются.
- Заголовки месяцев, два формата:
  - сокращённый: `янв. 2024, февр. 2024, март 2024, апр. 2024, май 2024, июнь 2024, июль 2024, авг. 2024, сент. 2024, окт. 2024, нояб. 2024, дек. 2024`;
  - полный: `Январь 2024 г.` … `Декабрь 2024 г.`.
  Парсер → `pandas.Period(freq="M")`. Неизвестный заголовок → ошибка качества `HDR_UNKNOWN_MONTH`.
- Пустая ячейка количества в месячных таблицах = 0 (продажи) / 0 (остаток). В транзакциях пустое количество → строка отбрасывается
  (`TX_EMPTY_QTY`).
- Строки-итоги: первая ячейка/«Номенклатура» = `Итого` или `Дата` = `Итого` → отбросить. Строки-подзаголовки (`Количество`,
  `нач. остаток`) → отбросить.
- Колонки `Итого`, `Продажи 2024`, `Ср мес …`, `Сумма последние 12 мес`, `Кэф. …`, `Запас` — производные, **не используются**
  в расчёте (только для воспроизведения метода менеджера в бэктесте).
- Даты транзакций: строка `dd.mm.yyyy H:MM:SS` (час может быть без ведущего нуля) → `%d.%m.%Y %H:%M:%S`.
- Числа: допускаются `int`, `float`, строки с `,` или `\xa0` → нормализовать.
- Единицы (`Ед.`/`Ед.изм`): `шт`, `м`, `упак`, `компл`. Количества — `float` (есть дробные остатки в метрах).

## 2. Каноническая модель (`ekt_core/schema.py`, pandas DataFrame + dataclass-описания колонок)

| Таблица | Колонки (тип) | Ключ |
|---|---|---|
| `suppliers` | supplier_id (str: `SE`,`IEK`), name | supplier_id |
| `channels` | channel_id (str), supplier_id, name, lead_time_days (int), lead_time_source (`data`/`default`/`user`), review_days (int), min_order_value_kzt (float\|null), is_fast (bool) | channel_id |
| `skus` | sku_id, supplier_id, supplier_article, name, uom_sales, uom_purchase, purchase_factor (float, ≥1), min_order_qty (float, в ед. закупки), order_multiple (float, в ед. закупки), abc (`A`/`B`/`C`/`N`/null), abc_source (`data`/`computed`), unit_cost_kzt (float\|null), lifecycle (`active`/`new`/`eol`/`discontinued`/`made_to_order`), launch_date (date\|null), section (str\|null), group (str — линейка/серия), markers (list[str]), marker_color (str\|null), default_channel_id | sku_id |
| `sales_monthly` | sku_id, month (Period M), qty (float, нетто, может быть <0) | sku_id+month |
| `sales_lines` | sku_id, ts (datetime), doc_key (str `{год}-{номер}`), doc_type (str), qty (float), uom (str), warehouse (str), client_hash (str\|null), price (float\|null) | sku_id+doc_key |
| `stock_opening` | sku_id, month (Period M), qty (float, остаток на 1-е число) | sku_id+month |
| `stock_current` | sku_id, as_of (date), free, reserved, retail, showcase, tz, rc (float), is_estimate (bool) | sku_id |
| `inbound` | sku_id, doc_id, channel_id, order_date (date\|null), eta (date), qty (float, ед. продажи), source (`doc`/`comment`/`column`/`default`) | sku_id+doc_id |
| `season_prior` | supplier_id, month_num (1–12), coef (float, среднее = 1), source (`partner_file`) | supplier_id+month_num |
| `notes` | sku_id, kind (`comment`/`name_suffix`/`section`/`marker`/`color`), ref (str: ячейка/лист), text (PII-очищенный) | — |
| `quarantine` | file, row, reason_code, raw (dict без ПД) | — |
| `dataset_meta` | dataset_id, as_of, files[{name, sha256, profile, rows}], created_at | — |

`as_of` = максимальная дата транзакций (ожидается 2026-09-22). Текущий месяц (сентябрь 2026) — **неполный**: исключается из истории
для прогноза, используется для оценки текущего остатка ИЭК и дневной проекции.

## 3. Systeme Electric (supplier_id `SE`)

### SE-1 `MOQ SystemElectric.xlsx` → профиль `se_moq`
- Лист `Лист_1`, строка 1 — заголовок: `№, Номенклатура, Номенклатура.Код, Артикул, Кратность`; строка 2 пустая.

- ~555 строк.

### SE-2 `Динамика продаж_Syseme Electric_2025-2026.xlsx` → `lines`
- Лист `Лист_1`. Заголовок: `Дата, Номер, Документ, Код, Номенклатура, Ед., Склад, Количество`. Последняя строка `Итого`.
- Брать только `Документ` начинается с `Расходная накладная`. Исключить `Заказ покупателя` (3 строки), `Приходная накладная`,
  прочие → `TX_DOC_TYPE_EXCLUDED`.
- `doc_key = f"{ts.year}-{Номер}"` — **номера сбрасываются каждый год** (1 219 номеров встречаются в двух годах).
- Строки до 2025-01-01 (≈298, в основном отрицательные корректировки) → исключить, `TX_BEFORE_2025`.
- Отрицательные количества в 2025+ (единицы) → `returns` (учитываются нетто в дневной проекции, не в поиске разовых).
- 13 пустых количеств → `TX_EMPTY_QTY`. Склад везде `Алматы`. Клиента и цены **нет** → `client_hash`, `price` = null.
- ~77 312 строк, 565 SKU.

### SE-3 `Ежемесячные остатки SystemElectric 2024-2026.xlsx` → `stock_opening`
- Заголовок строка 1: `№, Номенклатура, Номенклатура.Код, Ед.изм, янв. 2024 … сент. 2026`; строки 2–3 пустые; колонки `Итого` нет.
- Значение = остаток на начало месяца; пусто = 0. ~701 SKU.

### SE-4 `Ежемесячные продажи в кол-м выражении SystemElectric 2024-2026.xlsx` → `sales_monthly`
- Лист `Лист_1`: `Номенклатура, Номенклатура.Код, Артикул, Кратность, янв. 2024 … сент. 2026, Итого`; строка 2 = `Количество`;
  последняя строка `Итого`. Скрытый лист `Лист1` (копия сезонности в деньгах) — игнорировать.
- `Кратность` здесь может быть 0 при ненулевой в SE-1 → приоритет у SE-1, расхождение → `MOQ_MISMATCH` (info).
- Отрицательные значения (нетто-возвраты) встречаются (SE ≈323 ячейки у 187 SKU; ИЭК ≈234) — сохраняем, чистит движок.

### SE-5 `Сезонность SystemElectric 2024-2026.xlsx` → `season_prior`
- Лист `Лист1`. Строки 4–6 — выручка по месяцам (₸) 2024–2026. Строка 10 — заголовок таблицы; колонка **L `СЕЗОННОСТЬ`**,
  строки 11–22 (янв…дек) — коэффициенты. `N15` — «Поправка 2026/2025». Нормировать коэффициенты к среднему 1.

### SE-6 `Товар в пути_SystemElectric на 22.09.2026.xlsx` → `master` (фактически **рабочая таблица менеджера**)
- Лист `TDSheet`, **заголовок в строке 2** (строка 1 — объединённая группа `СКЛАДЫ` AT1:BB1). Скрытый лист `Лист1` игнорировать.
- Колонки (индекс/буква):
  `A №, B Артикул поставщика, C Код 1с, D Наименование, E Категория 2026 ('1','2','3','5','7' строкой), F СС реал (себестоимость ₸)`,
  `G…AO` месяцы `Январь 2024 г.`…`Сентябрь 2026 г.` (+ вставки `S Продажи 2024`, `T Ср мес 2024`),
  `AP Сумма последние 12 мес`, `AQ Ср мес за последние 12 мес`, `AR Кэф. Роста`, `AS Кэф. Сез-ти`,
  `AT Витрина, AU Остаток ТЗ, AV РЦ ЕКТ  Рыскулова (двойной пробел), AW Розничный склад, AX Остаток, AY Зарезервировано,
  AZ Свободный остаток, BA Запас, BB Заказ (пусто), BC СЭ в пути 24.09, … BH Вес (пусто)`.
- Искать колонки **по тексту заголовка** (нормализуя пробелы), не по букве.
- → `skus`: supplier_article, abc (`1→A, 2→B, 3→C, 5→B` + marker `line_new`, `7→N`), `unit_cost_kzt = СС реал` (0 → null).
- → `stock_current`: `free=Свободный остаток, reserved=Зарезервировано, retail=Розничный склад, showcase=Витрина, tz=Остаток ТЗ,
  rc=РЦ ЕКТ Рыскулова` (rc в доступный остаток не входит по умолчанию, параметр `include_rc`). `is_estimate=False`, `as_of=2026-09-22`.
- → `inbound`: `СЭ в пути 24.09` > 0 (7 SKU, 50 160 шт). **ETA — в комментарии ячейки BC** (`20.10`, `01.10`) → `eta = dd.mm.<год as_of>`
  (если получилась дата раньше `as_of − 30 дн` → +1 год), `source='comment'`; без комментария → `eta = as_of + default_inbound_eta_days`
  (параметр, 14), `source='default'`. `channel_id='SE-MAIN'`, `doc_id='SE-TRANSIT-{sku}'`.
- Формулы менеджера (для бэктеста «метод менеджера»):
  `AP = SUM(AC:AO)` — **13 месяцев** (сен-2025…сен-2026, включая неполный) / 12 в AQ;
  `AR = SUM(июн–авг 2026)/SUM(июн–авг 2025) − 1`; `AS = SUM(сен–ноя 2025)/SUM(июн–авг 2025) − 1`;
  `BA = (AZ+AU+AW+BB+AT+BC)/AQ` (месяцев покрытия).
- Условное форматирование: `AR:AS` < −0.3 или > 0.3; `BA` < 1 или > 4 → параметры `significant_coef=0.3`, `cover_min=1`, `cover_max=4`.
- ~497 строк.

### IEK-6 `Путь ИЭК 22.09.2026.xlsx` → `master_iek` + `inbound` + `notes`
- Лист `Лист4`. Заголовок строка 1: `Код 1с, Артикул ИЭК, " Наименование"` (ведущий пробел) + 6 колонок поставок, заголовок вида
  `РФ УТ-7583 от 31 августа 2026 г. (поступление до 10.10.2026)` — **между `2026` и `г.` неразрывный пробел `\xa0`**, бывают двойные пробелы.

  (ожидается РФ ≈38 (35 и 40), ПП 24, УТ 12), `source='data'`. `is_fast` = минимальный срок.
  → `inbound`: каждая непустая ячейка поставки (≈300 SKU, ≈110 тыс. ед.; 6 SKU в нескольких поставках).
  `default_channel_id` SKU = канал его последней поставки, иначе `IEK-PP` (параметр).
- **Секции**: строки, где `Код 1с` и `Наименование` пусты, а во 2-й колонке текст/число: `НОВИНКИ`, `Расширение 3кв`,
  `Расширение 1кв 24`, `Расширение 2кв 24`, `Расширение 3кв 24`, `Е-про`, `2 кв 2025`, `4 кв 2025`, `2кв 2026`, либо `1` (разделитель).
  Текст секции → `skus.section` для последующих строк до следующей секции; из текста → `launch_date` = первый день квартала
  (`Nкв YY`/`N кв YYYY`; «Расширение 3кв» без года → null + `SECTION_NO_YEAR`); `НОВИНКИ` → marker `new`.
- **Суффиксы в названиях** (60 шт): `ЗАКУПАЮТСЯ БУХТАМИ, САДЯТСЯ МЕТРАЖОМ` (6; `uom_purchase='бухта'`, `purchase_factor` = число из `305м`)
  и `ЗАКУПАЮТСЯ УПАКОВКАМИ, САДЯТСЯ ШТУКАМИ` (54; `uom_purchase='упак'`, `purchase_factor` = число из последних скобок `(4)`).
  Суффикс удалить из отображаемого имени, сохранить в `notes`.
- **Маркеры**: `!!!`, `***` (112, GENERICA), `NEW` (129), `E-PRO` → `skus.markers`.
- **Комментарии ячеек** (6): `замена MKK11-20-20`, `Замена120100074`, `EOL`, `под заказ`. Текст комментария openpyxl содержит автора
  (`Aleksey.K:\n…`, `Zakup-12:\n…`) — **автор = персональные данные, удалить** до сохранения (PII-guard). → `notes(kind='comment')`.
- **Заливка** (жёлтая FFFF00 ~117 строк, зелёная 92D050 = «упаковками/штуками», оранжевая FFC000, тема-цвета) — сохранить сырой цвет
  в `marker_color`, **не интерпретировать** (смысл уточняется).
- **Дубликаты кодов**: 7 (`220400107_`…`220400113_`) → первый + `DUP_CODE`.
- ~2 641 строка.

## 5. Детектор профилей (`ekt_adapters/detect.py`)

Для каждого листа — первые 5 строк → множество нормализованных заголовков (lower, пробелы схлопнуты, `\xa0` → пробел).
Профиль выбирается по обязательным маркерам:

| Профиль | Обязательные заголовки | Поставщик |
|---|---|---|
| `lines` | дата, номер, документ, код, количество | по справочнику SKU (после загрузки всех файлов) |
| `se_moq` | номенклатура.код, артикул, кратность, и нет месячных колонок | SE |
| `iek_moq` | код 1с, артикул поставщика, мин. разр. к отгр. | IEK |
| `sales_monthly_se` | номенклатура.код, артикул, кратность, ≥12 месячных | SE |
| `sales_monthly_iek` | номенклатура.код, ≥12 месячных, строка 2 = количество, нет «ед.» | IEK |
| `stock_se` | номенклатура.код, ед.изм, ≥12 месячных | SE |
| `stock_iek` | номенклатура.код, ед., строка 3 = нач. остаток | IEK |
| `master_se` | код 1с, категория 2026, свободный остаток | SE |
| `master_iek` | код 1с, артикул иэк, ≥1 колонка «поступление до» | IEK |
| `season` | «сезонность», «коэф. сезонности» | по имени листа/файла: `Сезонность ИЭК`→IEK, иначе SE; при сомнении — вопрос в UI |

Неизвестный файл → `status='unknown'` → мастер ИИ-импорта (SPEC_AI AI-4) → пользовательский профиль YAML (`profiles/custom/`).

## 6. Правила качества (`ekt_adapters/quality.py`)

| Код | Уровень | Описание |
|---|---|---|
| `HDR_UNKNOWN_MONTH` | error | не распознан месячный заголовок |
| `TX_EMPTY_QTY` | warn | пустое количество в транзакции |
| `TX_DOC_TYPE_EXCLUDED` | info | исключены не-расходные документы |
| `TX_BEFORE_2025` | info | строки ранее начала истории транзакций |
| `TX_UNKNOWN_SKU` | warn | SKU отсутствует в справочниках поставщиков (карантин) |
| `TX_NEGATIVE` | info | отрицательные строки (возвраты/корректировки) |
| `MONTHLY_NEGATIVE` | info | отрицательные месячные нетто-продажи |
| `RECON_LINES_VS_MONTHLY` | warn, если отношение вне [0.85; 1.15] | сверка Σ транзакций и месячного отчёта по поставщику-месяцу |
| `STOCK_IDENTITY` | info | доля нарушений `open[m+1] − open[m] + sales[m] ≥ 0` |
| `DUP_CODE` | warn | дубликат кода в справочнике |
| `MOQ_EMPTY`, `MOQ_ZERO`, `MOQ_MISMATCH` | warn/info | проблемы кратности |
| `STOCK_ESTIMATED` | warn | текущий остаток оценён |
| `INBOUND_ETA_DEFAULT` | info | ETA не найдена, взята по умолчанию |
| `SECTION_NO_YEAR` | info | секция без года |
