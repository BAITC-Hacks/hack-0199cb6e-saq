# PLAN — ЕКТ «Автозаказ поставщикам» (HACKALEM AI, кейс ТОО «Электрокомплект»)

Формат: хакатон **4 часа**, команда **3 человека**, код пишет **Codex**, репозиторий **приватный**.
Полный объём, без сокращений. Порядок задач внутри потока = приоритет (сначала то, без чего не пройдёт приёмка).

---

## 0. Цель и критерии успеха

| # | Критерий | Как доказываем |
|---|---|---|
| MH1 | Базовая потребность учитывает ВСЕ источники (история, остатки, в пути, категории, прогноз прироста) | `tests/acceptance/test_mh1_sources.py` + what-if в UI |
| MH2 | Сезонность и устойчивый рост | `test_mh2_seasonality.py` + график с сезонным профилем |
| MH3 | Оценка и компенсация упущенного спроса (stockout) | `test_mh3_stockout.py` + переключатель «сырые/восстановленные» в карточке |
| MH4 | Выявление и исключение разовых крупных заказов | `test_mh4_oneoff.py` + отметки ✕ на графике + реальный кейс LOOP 210 000 шт |
| MH5 | Список, сгруппированный по поставщикам, с обоснованием каждой строки | `test_mh5_explain.py` + вкладки поставщиков, waterfall |
| OPT | Приоритизация по риску, MOQ/кратность, тренды по категориям, выгрузка заказа | срочность+дата дефицита, округление, /analytics, экспорт + черновик письма |
| AI | Локальный ИИ AI-1…AI-7, RU + KZ | `docs/SPEC_AI.md`, эпизод в видео |
| SEC | Приватность, объяснимость, устойчивость к выбросам, совместимость с 1С | `docs/SPEC_SECURITY.md`, экспорт в формате 1С |
| DOC | README: методология, алгоритм исключения выбросов, запуск | `README.md`, `docs/METHODOLOGY.md` |

Запрещено кейсом и соблюдается архитектурно: автоматическая отправка заказа поставщику (в коде нет исходящей почты),
использование неанонимизированных данных клиентов (только `client_hash`).

## 1. Зафиксированные решения (не пересматриваем на хакатоне)

| ID | Решение | Почему |
|---|---|---|
| D1 | База спроса — **месячные отчёты** (32 полных месяца 2024-01…2026-08, обе поставщики) | Официальные цифры; совпадают с рабочей таблицей менеджера |
| D2 | Транзакции (2025-01…2026-09-22) — для поиска разовых строк, оценки дней наличия и дневной проекции | Только в них видны отдельные накладные |
| D3 | Вычитание разового объёма из месяца: `min(excess, max(0, monthly − tx_regular))` | Корректно при любом ответе партнёра про ×2 у SE; LOOP и IMT не вычитаются дважды |
| D4 | Остатки в месячных файлах = **остаток на начало месяца**; пусто = 0 | Явно в заголовке ИЭК; статистически подтверждено для SE (90% vs 72%) |
| D5 | Текущий остаток: SE — рабочая таблица менеджера; ИЭК — **оценка** (остаток на 01.09 − продажи 01–22.09), флаг `STOCK_ESTIMATED` | У ИЭК нет снимка на дату |
| D6 | Товар в пути: ИЭК — по документам с ETA; SE — колонка «в пути» + ETA из **комментариев ячеек** | Так в данных |
| D7 | Каналы ИЭК: РФ ≈38 дн, ПП ≈24 дн, УТ ≈12 дн (медиана ETA − дата документа); SE 45 дн по умолчанию; всё редактируется | Выведено из документов |
| D8 | Коридор покрытия 1–4 мес, значимость коэффициентов ±30% | Условное форматирование в таблице менеджера |
| D9 | Прогноз — по **количеству**; денежные файлы сезонности — только как априорная информация | В деньгах инфляция (ИЭК −15% шт при ровной выручке) |
| D10 | Стек: Python (uv) + FastAPI + Next.js 16; SQLite; без Docker на демо | Минимум интеграционных рисков за 4 ч |
| D11 | ИИ локально (Ollama): Qwen3 (Apache-2.0) + bge-m3 + faster-whisper + Natasha; ИИ не считает количества | Приватность, объяснимость, закон РК об ИИ |
| D12 | Реальные данные — вне репозитория (`C:\ekt-data`), Codex их не видит; тесты только на синтетике | Коммерческая тайна; Codex отправляет контекст в облако |
| D13 | Интерфейс и объяснения RU/KZ; экспорт для 1С и письмо поставщику — RU | Требование команды; 1С и поставщики — RU |
| D14 | Утверждение по правилу «четырёх глаз» (утверждающий ≠ отправивший), настраиваемо | Кейс: подтверждение ответственным сотрудником |

## 2. Архитектура

```
 Браузер ──► Next.js 16 (web/, :3000, CSP, i18n ru/kk)
                 │  rewrites /api/* (SSE — через route handler)
                 ▼
            FastAPI (ekt_api, 127.0.0.1:8000) ── SQLite (var/app.db: сессии, заказы, аудит, подсказки ИИ)
             │        │                  └── var/datasets/{id}/*.parquet (нормализованные данные, кэш прогонов)
             │        ▼
             │   ekt_adapters ── xlsx_safe → detect(профиль) → se/iek/generic → quality → PII-guard
             │        ▼
             │   ekt_engine ── cleaning → oneoff → stockout → classify → seasonality → forecast
             │                 → policy → projection → explain → RunResult (детерминированно)
             ▼
          ekt_ai ── providers (Ollama 127.0.0.1:11434 | fake) · router · tools(read-only) · agent · grounding
                    · enrich/search/analogs · notes · importer · briefing · letter · voice · pii
```

Данные: `DATA_DIR=C:\ekt-data\SE`, `C:\ekt-data\IEK` (копия с рабочего стола в ASCII-путь, вне OneDrive).

## 3. Команда и потоки

У каждого человека **два параллельных потока Codex** (задачи идут одновременно, человек ревьюит и склеивает).

| Человек | Поток 1 | Поток 2 | Владеет |
|---|---|---|---|
| **A — данные/алгоритм** | A1: движок (очистка → прогноз → политика → объяснения → приёмка) | A2: поиск/обогащение, аналоги, разбор пометок, бэктест | `src/ekt_engine`, `src/ekt_ai/{enrich,search,analogs,notes}`, `tests/engine`, `tests/acceptance` |
| **B — интерфейс/дизайн** | B1: каркас, таблица, карточка SKU, заказы, аналитика | B2: ИИ-интерфейс (чат, поиск, брифинг, подсказки, импорт, голос), логин, аудит | `web/` |
| **C — данные/API/безопасность** | C1: адаптеры, качество, синтетика-xlsx, API, заказы, экспорт | C2: ИИ-бэкенд (провайдеры, агент, брифинг, импорт, голос, PII), безопасность, документы | всё остальное |

Роль в демо: B — ведёт экран и монтаж видео; A — цифры и методология; C — безопасность и ИИ.

## 6. Работа с Codex

- **Локально Codex CLI** у каждого (в своей ветке/worktree) — основной режим; **облачные задачи Codex** — для фоновых параллельных
  задач (например, A-2, C-4, C-8). В облаке нет Ollama и реальных данных → тесты с фейковыми провайдерами.
- Ветки: `a/<task>`, `b/<task>`, `c/<task>` → PR → быстрое ревью владельцем соседней зоны (≤5 мин) → squash в `main`.
  Merge не реже раза в 30–40 мин. Каждый владеет своими папками → конфликтов почти нет.
- Общие файлы: `pyproject.toml`/`uv.lock` — добавляет зависимости только C (остальные пишут в чат команды «нужен пакет X»);
  `web/package.json` — только B; `contracts/` — только C.
- Промпты — из `docs/TASKS.md` дословно, с подстановкой. Каждый промпт требует: читать AGENTS.md и указанные разделы спеки,
  не трогать чужие папки, прогнать тесты, вывести список файлов.
- **Реальные данные прогоняют только люди** в отдельном терминале (`uv run python -m ekt_adapters.cli load C:\ekt-data`) — Codex не
  запускает команды с DATA_DIR. Результаты прогона не копировать в промпты Codex дословно (только агрегаты при необходимости).
- Чек-лист ревью PR: тесты зелёные; нет xlsx/csv/db/.env; контракт не изменён; нет магических чисел; тексты в i18n; нет внешних URL.

## 7. Интеграция и калибровка на реальных данных (A-8, чекпоинт 2)

Проверить глазами (ожидания — SPEC_DATA §7):
1. Загрузка 12 файлов: все профили распознаны; отчёт качества содержит: пустые количества (13 SE, 18 ИЭК), строки «Итого»,
   «Заказ покупателя»/«Приходная накладная», дубликаты кодов (1 в MOQ ИЭК, 7 в «Путь»), неизвестный SKU `130200305_` (LOOP),
   сверку «транзакции vs месяц» (SE ≈×2, ИЭК ≈×1, июнь-2025 ИЭК ×2 из-за LOOP).
2. IMT35100 (`030200192_`): крупные строки повторяются почти каждый месяц → **не** разовые (`REGULAR_LARGE_BUYER`); вычитания нет.
3. Позиции со stockout (≥1 месяц с нулевым остатком на начало): восстановление > 0, в пределах cap.
4. ИЭК ВА47-29 16А (`010500006_`): в пути 18 000 (ПП, 01.10) + 12 000 (УТ-8233, 30.09) — отражено в проекции.
5. Кабели (6 позиций, бухта 305 м) и 54 позиции «упаковками/штуками»: заказ в единицах закупки.
6. Разумность: доля строк к заказу, суммы по поставщикам, число critical — обсуждаем, правим параметры в `config.py`, не код.

## 8. Риски

| Риск | Митигация |
|---|---|
| Codex «уплывает» от спеки, потоки не стыкуются | Замороженный `contracts/api.ts` + моки, AGENTS.md, частые merge, чекпоинты |
| Локальная LLM медленная | Тиры моделей, прогрев, `think=false`, стрим, предрасчёт обогащения и брифинга, детерминированный роутер интентов |
| Слабый казахский у модели | Детерминированные KZ-шаблоны объяснений; глоссарий; вычитка носителем; опционально KazLLM для финальной формулировки |
| Нестабильный вызов инструментов малыми моделями | Роутер интентов для ключевых сценариев, ≤8 инструментов, few-shot, 1 повтор, fallback-ответ по шаблону |
| Расхождение SE ×2 | Решение D3 + предупреждение в отчёте качества + вопрос партнёру |
| Нет текущего остатка ИЭК | Оценка + флаг + параметр ручного ввода остатка |
| Демо падает вживую | Видео записано заранее; кэш прогона; ИИ отключаем — ядро работает |
| Windows: кириллица/пробелы в путях, OneDrive | Данные в `C:\ekt-data`; все пути через `pathlib`; тесты на именах с кириллицей и двойными пробелами |
| Утечка данных через Codex/видео | D12; в видео — синтетика или размытие, если видео публичное |
