## Проблема и пользователь

Проект посвящён подготовке рекомендованных заказов поставщикам для ТОО «Электрокомплект». Основной пользователь — менеджер по закупкам, работающий с ассортиментом Systeme Electric и ИЭК.

Чтобы определить потребность, закупщику нужно сопоставить историю продаж, складские остатки, ожидаемые поставки и условия закупки. Продажи могут занижать спрос, когда товара нет на складе; разовая крупная покупка, наоборот, может завышать прогноз. Сезонность и устойчивый рост дополнительно меняют будущую потребность.

Цель проекта — дать закупщику список рекомендуемых количеств по поставщикам с понятным обоснованием каждой строки. Решение о заказе остаётся за ответственным сотрудником.

## Данные и интеграции

Входные данные кейса — 12 Excel-выгрузок из 1С по двум поставщикам, по шесть файлов на каждого. Их форматы описаны в [SPEC_DATA.md](SPEC_DATA.md). Таблица ниже описывает назначение источников по спецификации, а не подтверждённую работу импорта.

| Источник | Для чего нужен |
|---|---|
| Месячные продажи | История спроса в количестве: полные месяцы с января 2024 по август 2026; сентябрь 2026 в исходном срезе неполный |
| Строки расходных накладных | Анализ отдельных крупных покупок и возвратов; детализация продаж с января 2025 по дату среза |
| Месячные остатки | Наличие товара на начало месяца и периоды возможного дефицита |
| MOQ и кратности | Минимальное количество и допустимый шаг закупки |
| Сезонность | Коэффициенты сезонного профиля поставщика; денежная сезонность служит дополнительной информацией, а потребность задаётся в количестве |
| Рабочая таблица SE / «Путь» ИЭК | Номенклатура, категории и доступные атрибуты, товар в пути и ожидаемые даты поступления |

По спецификации срез данных — 22.09.2026. Текущий остаток SE берётся из рабочей таблицы менеджера. Для ИЭК снимок на дату отсутствует: предусмотрена оценка по остатку на начало сентября и последующим продажам, которую нужно явно отличать от фактического остатка.

Для корректной закупки важны различия единиц: метры и бухты, штуки и упаковки. Код номенклатуры 1С хранится строкой с сохранением ведущих нулей, регистра и завершающего `_`.

Реальные выгрузки хранятся вне репозитория. Для разработки и воспроизводимой проверки спецификация предусматривает синтетические наборы. Сырые идентификаторы клиентов не допускаются; при наличии клиентского признака используется обезличенный `client_hash`.
