# SPEC_SECURITY — безопасность, приватность, юридические требования

## 1. Модель угроз (кратко, STRIDE-lite)

| Актив | Угроза | Контроль |
|---|---|---|
| Продажи, остатки, себестоимость, условия поставщиков (коммерческая тайна) | утечка через репозиторий, Codex, логи, видео, ИИ-облако | данные вне репо, Codex только синтетика, логи без значений, локальный ИИ, правила видео (§6) |
| Данные клиентов (ПД) | использование неанонимизированных ID | только `client_hash` (HMAC, ключ у EKT), отклонение файлов с сырыми ID |
| ПД сотрудников в комментариях Excel | сохранение/показ/передача в LLM | PII-guard до сохранения (SPEC_AI §10) |
| Заказ поставщику | несанкционированная отправка/изменение | нет исходящей почты; статусы; RBAC; «четыре глаза»; аудит |
| Загрузка xlsx | zip-бомба, XXE, макросы, внешние ссылки, формулы | `xlsx_safe` (§2.2) |
| Экспорт | формульная инъекция в Excel/CSV | экранирование (§2.6) |
| Веб-сессия | кража cookie, CSRF, XSS, clickjacking | HttpOnly+SameSite=Strict, CSRF-токен, CSP с nonce, frame-ancestors none |
| ИИ | prompt-injection через данные, выдуманные числа, выход за полномочия | инструменты только на чтение, `<data>`-разделители, заземление, лимиты |
| Ollama | доступ извне | только 127.0.0.1, актуальная версия |
| Цепочка поставок | уязвимые/несовместимые по лицензии зависимости | lock-файлы, pip-audit, npm audit, проверка лицензий, gitleaks |

## 2. Контроли для реализации

### 2.1 Данные и репозиторий (C-0, C-8)
- `.gitignore`: `data/ var/ .env* *.xlsx *.xls *.xlsm *.csv *.parquet *.db *.sqlite *.log node_modules/ .next/`.
- `scripts/check_no_data.py` (pre-commit + CI): падает, если в индексе есть файлы с этими расширениями или > 1 МБ вне `web/public`.
- pre-commit: ruff, gitleaks, check_no_data. CI (GitHub Actions): те же + pytest + web lint/typecheck/build + pip-audit + `npm audit --omit=dev`
  + проверка лицензий (`pip-licenses --fail-on="GPL;AGPL;LGPL"` ± исключения согласовать, `license-checker --failOn "GPL;AGPL"`).
- `scripts/anonymize_clients.py`: утилита для стороны EKT: колонка клиента → `HMAC-SHA256(key, normalize(id))` hex[:16]; ключ из
  `CLIENT_HASH_KEY` (остаётся у EKT); исходная колонка удаляется. Наш сервис принимает только `client_hash`.
- Детектор сырых клиентских колонок в адаптерах: заголовки `контрагент|клиент|покупатель|бин|иин|телефон|e-?mail|адрес` без суффикса
  `hash` → `CLIENT_ID_RAW` (error), файл отклоняется.

### 2.2 Безопасная загрузка xlsx (`ekt_adapters/xlsx_safe.py`, C-1)
- Разрешены только `.xlsx` (сигнатура `PK\x03\x04` + наличие `[Content_Types].xml`); `.xlsm/.xls/.xlsb` → отказ; `xl/vbaProject.bin` → отказ.
- Лимиты: файл ≤ 50 МБ; записей в zip ≤ 10 000; суммарно распаковано ≤ 200 МБ; отношение распаковано/сжато на запись ≤ 200
  (файл MOQ ИЭК с кэшем внешней ссылки ~41 МБ должен проходить).
- `openpyxl.load_workbook(..., data_only=True, keep_links=False, read_only=<нет комментариев>)`; установлен `defusedxml`.
- Разбор в отдельном процессе (`concurrent.futures.ProcessPoolExecutor`, таймаут 60 с); ошибки → `Problem` без стека.
- Имя файла: хранить как `uuid4`; оригинальное имя — только для отображения, нормализованное (NFC, без управляющих, ≤ 120 символов).
- Сырые файлы удаляются после разбора; хранятся sha256 и нормализованные таблицы.

### 2.3 Аутентификация и авторизация (C-5)
- argon2id (`argon2-cffi`, параметры по умолчанию библиотеки), пароли ≥ 10 символов для демо-пользователей.
- Серверные сессии (SQLite), cookie `ekt_session`: `HttpOnly; SameSite=Strict; Path=/`; `Secure` при `ENV=prod`; TTL 8 ч; ротация при логине.
- CSRF: токен сессии в `User.csrf_token`, заголовок `X-CSRF-Token` на всех изменяющих запросах.
- RBAC декоратором `require_role(...)` на каждом роуте; проверка «четырёх глаз» в сервисе заказов (не только в UI).
- Rate limit (slowapi): логин 5/мин/IP, ИИ 20/мин/пользователь, what-if 30/мин.

### 2.4 Веб-заголовки (B-0/B-6, `web/proxy.ts` + `next.config.ts`)
`Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<n>' 'strict-dynamic'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; media-src 'self' blob:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`
(в dev допускается `'unsafe-eval'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
`Permissions-Policy: microphone=(self), camera=(), geolocation=()`, `Strict-Transport-Security` (prod), `X-Frame-Options: DENY`.
Демо запускать production-сборкой (`next build && next start`).

### 2.5 API (C-5)
- Uvicorn только `127.0.0.1`. CORS выключен (same-origin через Next).
- Валидация pydantic, лимиты длины строк/массивов, запрет лишних полей (`extra="forbid"`).
- SQLAlchemy ORM/параметризованные запросы; никакой конкатенации SQL.
- Ошибки — `Problem` без трейсбэков; трейсбэки только в локальный лог.
- structlog JSON: request_id, user, route, статус, длительность; **без** значений продаж, названий ПД, текстов вопросов ИИ.

### 2.6 Экспорт (C-7)
Строки, начинающиеся с `=`, `+`, `-`, `@`, `\t`, `\r` → префикс `'`; в xlsx явный тип `s`; без формул; CSV — UTF-8 BOM, `;`.
Экспорт `1c_xlsx`/`manager_xlsx` — только утверждённых заказов; все экспорты — в аудит.

### 2.7 Аудит (C-5)
Только добавление, цепочка sha256 (SPEC_API §5), эндпоинт проверки; удаление/изменение записей не предусмотрено API.

### 2.8 ИИ (C-2, C-3, C-6) — SPEC_AI §11.

### 2.9 «Без автоматической отправки» — закреплено
В коде нет `smtplib`/почтовых SDK/внешних HTTP (тест `tests/security/test_no_egress.py`: grep по `src/` на запрещённые импорты

## 5. Codex и облако
Codex отправляет контекст (код, спеки, вывод команд) в облако OpenAI. Поэтому: реальные файлы и их выгрузки в промпты не попадают;
Codex не запускает команды с `DATA_DIR`; в спецификациях — только структуры и агрегаты. Сверить с правилами хакатона и условиями партнёра.

## 6. Видео и публичность
Если видео/демо будут публикованы: показывать синтетический датасет (или размыть коды/названия/количества/суммы реальных данных),
не показывать себестоимость; в кадре — индикатор «офлайн». Если видео только для жюри — реальные данные допустимы по согласованию с партнёром.
